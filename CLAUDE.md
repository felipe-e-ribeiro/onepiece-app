## Project Overview

One Piece manga collection tracker — a fully static site generated by a Python pipeline and served via S3 + CloudFront. There is no runtime server; all HTML is rendered at build time by GitHub Actions.

## Commands

### Local Testing (Docker)

```bash
docker build -t onepiece-pipeline .
docker run -p 8080:8080 onepiece-pipeline
# Open http://localhost:8080
```

The container runs `DRY_RUN=true`: skips S3 checks, downloads all images, serves `output/` on port 8080.

### Run Pipeline Manually

```bash
cd website
pip install -r ../requirements.txt
# With S3 (normal mode):
BUCKET_NAME=your-bucket python volume_update.py
# Without S3 (local output only):
DRY_RUN=true python volume_update.py
```

### Trigger GitHub Actions

Push a change to `website/data/collection.yaml` on `main`, or trigger manually via **Actions → Update One Piece Collection → Run workflow**.

## Architecture

```
GitHub repo
  └── website/data/collection.yaml  (source of truth — edit to update owned volumes)
        │
        ▼ push to main
  GitHub Actions (.github/workflows/update.yml)
        │
        ▼ python website/volume_update.py
  Pipeline generates output/
    ├── index.html        (Jinja2 rendered at build time)
    └── static/
          ├── style.css   (copied from website/static/)
          ├── icon.png    (copied from website/static/)
          └── Volume_N.webp  (downloaded from Fandom wiki, skipped if already in S3)
        │
        ▼ aws s3 cp / aws s3 sync
  S3 Bucket
        │
        ▼
  CloudFront → onepiece.felipeduribeiro.com.br
```

## File Structure

```
website/
  volume_update.py      # Pipeline: scrape wiki, download images, render HTML
  owned.py              # Parses data/collection.yaml into an Owned object
  data/collection.yaml  # Owned volumes (ranges like 1-65) and databooks
  templates/index.html  # Jinja2 template — rendered to output/index.html
  static/               # Permanent assets committed to git (css, icon, fallback image)
requirements.txt        # All Python deps (scraping + Jinja2 + boto3)
Dockerfile              # Local test only — DRY_RUN=true, serves on :8080
.github/workflows/
  update.yml            # GitHub Actions: triggers on collection.yaml change
```

## Key Details

- **No Flask, no SQLite, no server runtime.** The pipeline renders `index.html` directly from Jinja2 and pushes static files to S3.
- **Image deduplication:** Pipeline lists `s3://BUCKET/static/Volume_*.webp` via boto3 before downloading — skips any image already in S3. `DRY_RUN=true` disables this check and downloads everything.
- **Upload strategy:** `index.html` is always overwritten (`s3 cp`); images use `s3 sync` without `--delete` (images only accumulate, never removed from S3).
- **AWS secrets in GitHub:** `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `BUCKET_NAME`. Add `CLOUDFRONT_DISTRIBUTION_ID` and uncomment the invalidation step in the workflow when CloudFront is configured.
- **Hardcoded region:** `us-east-1` in the workflow — change `aws-region` if the bucket is in another region.
- **Manual arc override:** Volume 111 is forced to `Elbaph_Arc` in `volume_update.py` because the wiki data is incorrect.
- **Owned ranges:** `collection.yaml` uses range syntax (`1-65`, `100-112`); `owned.py` expands them into a set.
- **No test suite** exists in this project.
