## Project Overview

One Piece manga collection tracker — a Flask web app that shows which volumes the user owns, with cover images fetched from the One Piece Fandom Wiki and stored in SQLite.

## Commands

### Local Development

```powershell
cd website
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app.py          # serves at http://0.0.0.0:5000
```

### Data Pipeline (regenerates database + cover images)

```powershell
cd website
pip install -r requirement-pipeline.txt
python volume_update.py
```

This scrapes the Fandom Wiki, downloads cover images as `.webp` into `static/`, and writes `my_database.db`.

### Docker

```powershell
cd website
docker build -t onepiece-app:latest .
docker run -p 5000:5000 onepiece-app:latest
```

### Kubernetes / Helm

```powershell
helm install onepiece-app ./onepieceapp-helm -f ./onepieceapp-helm/values.yaml
helm upgrade onepiece-app ./onepieceapp-helm
```

### CI/CD (GitLab — tag-triggered)

Push a semver tag to trigger the pipeline:
```powershell
git tag v1.x.y
git push origin v1.x.y
```

Pipeline stages: check-tag → generate-assets (runs `volume_update.py`) → build-and-push (multi-arch Docker image to Docker Hub).

## Architecture

```
website/
  app.py              # Flask entry point — read-only SQLite, one route (/)
  volume_update.py    # Data pipeline: scrape wiki → download images → write DB
  owned.py            # Parses data/collection.yaml into an Owned object
  data/collection.yaml  # Source of truth for owned volumes/databooks
  templates/          # Jinja2 (index.html, error.html)
  static/             # Cover images (.webp) + CSS — generated by pipeline
onepieceapp-helm/     # Helm chart for Kubernetes deployment
```

### Data Flow

1. **Pipeline** (`volume_update.py`): Fandom Wiki API → arc/volume metadata + cover URLs → parallel image download (8 workers) → WebP files in `static/` → SQLite `my_database.db`
2. **App** (`app.py`): `GET /` → read-only SQLite query → group editions by arc → Jinja2 render
3. **Ownership**: `owned.py` reads `collection.yaml` (range syntax like `1-65`, `100-112`) and marks `is_owned` in the DB during the pipeline run

### Database Schema

```sql
CREATE TABLE IF NOT EXISTS editions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    arc TEXT NOT NULL,
    volume_number INT,
    is_owned BOOLEAN
)
```

## Key Details

- **Read-only DB in app**: `app.py` opens SQLite with `mode=ro&immutable=1` — never write from the Flask app.
- **Two requirements files**: `requirements.txt` (runtime, 37 packages) vs `requirement-pipeline.txt` (scraping/image pipeline only — not needed to run the web server).
- **Manual arc override**: Volume 111 is hardcoded to "Elbaph Arc" in `volume_update.py:215-216` because the wiki data is incorrect.
- **Telemetry**: OpenTelemetry is wired up in `telemetry.py` but `setup_telemetry(app)` is commented out in `app.py`.
- **Databooks**: `owned.py` handles databook entries (yellow, blue, red) separately from numbered volumes.
- **No test suite** exists in this project.
